Shared parser reads day-first dates month first

The shared parser interprets dates as month/day even for tenants whose locale writes day/month. R-41200 intended 7 April but received 4 July. R-41201 reports the reverse. Correct parsing must use the agreed date format rather than assume month first. Keep this cause separate from the booking-form hint defect.

Booking-v3 prints a month-first hint for day-first tenants

Booking-v3 displays MM/DD/YYYY, so people follow a month-first instruction while the form reads the date in the tenant’s day-first order. The affected path is a form report from a day-first tenant running booking-v3. Booking-v2’s DD/MM/YYYY hint does not have this mismatch. Correct the displayed hint to match the form’s interpretation and validate that the same entered date yields the intended calendar date.
